## 2. P2-1 — A3 + 조회 포트 계약

### 현재 [사실]
- `RedisRealtimeSnapshotReader` `MAX_AGE=5분`, `fresh()`: 300초 초과 값은 버려 STALE 구간이 없음. 레거시 쓰기 TTL 5분(`RedisRealtimeStationStore`).
- `RealtimeStationStatus`는 `int rackTotalCount`, `double sharedRate`(non-null). `RealtimeSnapshotValues`는 rack/shared가 null이면 항목 전체 폐기(명세 11.0 위반). `publicationEligible=false`가 "없음"(수량 미상으로 노출)으로 처리됨.
- `JdbcStationSearchAdapter`: `rs.getInt("rack_total_count")`가 NULL→0, `enrich`가 요청마다 Redis `findAll`, `shared` 미채움.
- `StationResponse`: `shared=null`, `realtimeStatus`·`realtimeAgeSeconds` 없음. `Station`: `int rackTotalCount`. 생성자 호출처 main 3곳·test 8곳.
- `PlanBikeRoute.fresh()` 300초 고정(E4에서 교체). 웹 `status.ts`는 5분 초과를 unknown 처리.
- `ApiResponse.ok(data)`뿐이라 `meta.partial/warnings` 지정 불가(`Meta`는 필드 보유).

### 변경
- 설정 `realtime.freshness.fresh-seconds=120`, `max-stale-seconds=600`(`@ConfigurationProperties`+`@DefaultValue`, 기동 시 `fresh < maxStale` 검증). `RealtimeFreshnessPolicy(Clock)`: `classify(updatedAt, now)` → FRESH/STALE/UNAVAILABLE, age=max(0, floor(now−updatedAt)), 미래 30초 초과는 UNAVAILABLE, 요청당 `now` 1회.
- 리더 `MAX_AGE`를 `max-stale-seconds`로, 레거시 쓰기 TTL 900초(X3).
- `RealtimeStationStatus` rack/shared nullable, null만으로 거부하지 않음(100 초과 shared도 그대로). gate 3상태 `Eligible/Ineligible/Missing`: versioned는 `publicationEligible==true && operationStatus=="ACTIVE"`일 때만 공개(D3), 어긋나면 **EXCLUDED**. STALE·수량 0을 폐쇄로 해석하지 않음.
- `Station`에 `Integer rackTotalCount`, `Double shared` 추가, **8-인자 호환 생성자 유지**(routing·기존 테스트 파일 미수정). Jdbc는 `getObject(..., Integer.class)`.
- `StationResponse`에 `realtimeStatus`, `realtimeAgeSeconds` 추가·`shared` 채움. 시각을 받는 매퍼(application 계층)로 이동.
- `ApiResponse.ok(data, Meta)` 오버로드, `WarningCode` 상수(`STALE_DATA` 등).
- 포트 확장(기존 `StationSearchPort` 4개 메서드 시그니처 유지, routing·place 사용): `findWithin(center, radius)`(반경 내 전체 후보+상태), `lookup(ids)`(FOUND/NOT_FOUND/EXCLUDED/UNAVAILABLE), `realtimeSummary()`(total/fresh/stale/unavailable+lastSuccessAt). Jdbc·InMemory에 단순 구현(R3에서 대체).
- 웹: `W:lib/types.ts` Station에 `realtimeStatus`·`realtimeAgeSeconds`, `status.ts`는 `realtimeStatus` 기준(STALE은 수량 표시+"갱신 지연", 대여 가능 필터 제외), `web/tests/behavior.test.mjs`의 301초 케이스 수정.

### 계약 변경
UNAVAILABLE 항목이 목록에서 사라짐(기존: null 수량 노출), `realtimeStatus`/`realtimeAgeSeconds` 추가, `shared` 값 제공.

허용: `realtime/**`(+test), `station/domain/Station.java`, `station/domain/StationSearchPort.java`(추가만), `station/infrastructure/**`, `station/presentation/StationResponse.java`와 매퍼, `station/application/**`, `global/response/ApiResponse.java`·`Meta.java`(추가만), 신규 `WarningCode`, `application.yml`(`realtime.freshness` 키 추가만), `W:lib/types.ts`·`status.ts`, `web/tests/behavior.test.mjs`. 금지: `routing/**`, `place/**`, `GlobalExceptionHandler`, `StationController`(목록 제외·partial 적용 최소 변경만 예외).

## 3. 단계 2 단위

### R — R3
- 카탈로그: MySQL `station` 불변 스냅샷(전체 행+공개 적격 플래그), 이름·주소 정규화값·자판 변환값·초성 사전 계산, 약 1km 셀 격자 인덱스, `volatile` 참조 교체, 시작 시 동기 적재+10분 주기, 실패 시 이전 본 유지, 미적재 시 `ApiException(SERVICE_UNAVAILABLE)`. `synchronized` 제거, `KoreanSearch` 정규식 `Pattern` 상수화(공개 시그니처·의미 유지, 정규화값 사전 계산 오버로드 추가).
- 스냅샷 캐시: 백그라운드 poller(5초), **요청 경로의 Redis 왕복 0회**. versioned: `GET current` 변경 시에만 `HGETALL v{n}`. legacy: `last-success-at` 변경 시 재적재+60초 안전 재적재. auto: 포인터는 있는데 Hash가 없으면 legacy(R2 의미 유지). Redis 장애 시 이전 스냅샷 유지(나이에 따라 STALE→UNAVAILABLE). `last-success-at`도 캐시해 상태 API가 사용.
- InMemory(local)도 같은 카탈로그·스냅샷 소스 추상화로 통합(권장).
- 무효화: 포인터 우선, legacy는 `last-success-at`+60초, TTL은 무효화에 사용하지 않음. 다중 인스턴스는 각자 poll(공유 상태 없음, 차이 ≤ 약 5초+α).
- 한계: MySQL fallback·DB gate·`FALLBACK_USED` 미구현, legacy는 gate 없음, versioned는 수동 Redis 기록으로만 검증.
- 허용: `station/infrastructure/**`, `realtime/**`, `station/domain/KoreanSearch.java`·`StationNameSearch.java`(시그니처 유지), 신규 카탈로그·격자·poller, `application-infra.yml`(readiness·catalog 키). 금지: `station/presentation/**`, `station/application/**`, 포트 시그니처, `global/**`, `routing/**`, `place/**`, `web/**`.

### A — A4 → A5
- A4: `GET /stations/{stationId}`(미존재·제외 404 `STATION_NOT_FOUND`, 공개 대상인데 스냅샷 없음 503 `REALTIME_DATA_UNAVAILABLE`), `GET /stations/realtime?stationIds=`(쉼표 문자열, 중복 제거 전 1~100개, 빈 항목·형식 오류 400 `INVALID_PARAMETER`, 첫 등장 순서 유지, `items/notFoundStationIds/excludedStationIds/unavailableStationIds` 항상 포함, 공개 대상이 있는데 반환 항목 0개면 503, 저장소 장애 503 `SERVICE_UNAVAILABLE`), `GET /status/realtime`(신규 `status` 패키지 컨트롤러, NORMAL/DELAYED/UNAVAILABLE, `lastUpdatedAt`·`ageSeconds`는 `last-success-at`, 없으면 null, `ingestion_run` fallback 미구현). 상세·Batch 응답은 `distanceMeters` 없는 별도 DTO. 기존 `StatusController` 미수정.
- A5: nearby 파라미터 `radius`(기본 1000, 100~5000), `limit`(기본 30, 1~100, 위반 `INVALID_LIMIT`), `sort`(distance/parkingBikeTotCnt/name), `onlyAvailable`(FRESH이면서 수량>0). 응답 `{center, radiusMeters, items}`. 처리 순서: 반경 내 전체 후보에 상태 결합→필터→정렬→limit, 동률 `stationId`, name은 NFC 정규화 후 코드포인트 비교. 결정표: STALE만 있으면 200+partial, 전부 UNAVAILABLE이면 503. `GlobalExceptionHandler.validationCode`에서 `radius`→`INVALID_RADIUS`, `limit`→`INVALID_LIMIT`(이 핸들러 수정은 A 단위 독점).
- 웹: `W:lib/api.ts` `nearby()`를 `radius`+`limit=100`, `.items`로 언랩해 `Station[]` 시그니처 유지. 백엔드·웹 같은 PR. `ApiContractTest` radius 관련 갱신.
- 허용: `station/presentation/**`, `station/application/**`, 신규 `status/**`, `GlobalExceptionHandler.validationCode`(radius·limit만), `ApiContractTest`, `W:lib/api.ts`·`types.ts`, 관련 웹 테스트. 금지: `station/infrastructure/**`, `realtime/**`, `routing/**`, `place/**`.

### E — E1 → E3 → E4
- E1: `place/PlaceSearchProvider`(keyword, address, reverse, category) + `KakaoPlaceSearchProvider`, `place/application/PlaceSearchService`(병합·중복 제거·대여소 보완). 컨트롤러는 검증·매핑만. 응답 계약 불변. `PlaceSearchControllerTest`는 provider mock 테스트와 MockRestServiceServer 기반 provider 테스트로 분리.
- E3: keyword ∥ subway를 virtual thread로 병렬(테스트 `ignoreExpectOrder`), Redis 캐시(D9, fail-open, local 비활성), 정규식 상수화.
- E4: provider별 timeout(D8, ORS 전용 설정 추가), `PlanBikeRoute` 전체 deadline(virtual thread future, 초과 시 cancel), GET retry 1회(`RetryTemplate`, 4xx·429 제외), 자체 circuit breaker(Place/Walking/Bicycle, count 창·실패율 임계·OPEN 30초·HALF_OPEN probe, `NO_ROAD_ROUTE`·4xx는 실패 미집계), bulkhead(Semaphore), OPEN 즉시 502, timeout 504 `EXTERNAL_API_TIMEOUT`, `PlanBikeRoute.fresh()`를 FRESH 기준(D2)으로 교체.
- 허용: `place/**`(+test), `routing/**`(`PlanBikeRoute` 포함), 신규 `global/http/**` 설정, 신규 `global/resilience/**`, `application.yml`(`kakao`·`ors`·`place.cache`·`provider` 키). 금지: `station/**`(읽기만), `realtime/**`, `global/exception/**`, `web/**`.

### O — O3
- `HandlerInterceptor`를 신규 `WebMvcConfigurer`에 등록(CORS 이후 실행되어 cross-origin에서도 429 바디·`Retry-After` 가능, servlet filter 금지). 초과 시 `RateLimitExceededException extends ApiException`(`getHeaders()`에 `Retry-After`), `ErrorCode.RATE_LIMIT_EXCEEDED`(429) 사용, 핸들러·`ApiException` 미수정. 정책 그룹 stations/status·places·routes, 키는 IP 해시. 저장소: Redis Lua 토큰버킷(`DefaultRedisScript`, Redis `TIME`), Redis 장애 시 로컬 fail-open, 로컬 버킷 맵 만료 정리, local 프로필은 메모리만. 대여소·상태 API는 메모리 limiter(D6).
- 허용: 신규 `global/ratelimit/**`, 신규 WebMvc 설정, 자체 테스트 클래스, `application*.yml`(`ratelimit` 키). 금지: `GlobalExceptionHandler`, `ApiException`, `WebCorsConfig`, 컨트롤러, `ApiContractTest`, `web/**`.
- 위험: 프록시 뒤에서 forwarding 설정이 틀리면 모든 사용자가 한 IP로 묶여 대량 429. 웹의 429 처리(Retry-After backoff)는 후속.

### 공유 파일 규칙
`application.yml`/`application-infra.yml`은 각 단위가 자기 최상위 키만 추가, 기본값은 `@DefaultValue`. A·R은 P2-1이 확정한 포트 의미를 바꾸지 않음. E는 R3가 바꾸는 `searchByName` 구현이 아니라 시그니처에만 의존.

### 리뷰 후속(미반영, 결정 필요)

- readiness에 `db` 유지 여부: R3 이후 요청 경로는 메모리 카탈로그만 사용하므로 MySQL 장애 시 적재된 인스턴스까지 빼는 것이 맞는지 결정.
- 공유 IP 정책: Vite 개발 프록시·CGNAT·신뢰 프록시 뒤에서 여러 사용자가 한 키로 묶이는 문제(forwarded 헤더 신뢰 범위, 키 단위).
- 웹 429 처리: `Retry-After` 기반 backoff와 사용자 안내.
- bulkhead 포화 응답 코드: 현재 502, 일시적 과부하 성격상 503 검토.
- `radius`/`limit` 타입 오류(숫자 아님)의 오류 코드: 현재 `INVALID_PARAMETER`, `INVALID_RADIUS`/`INVALID_LIMIT`로 통일할지.
- 사용되지 않는 `RedisRealtimeSnapshotReader`·`RedisRealtimeStationStore.findAll` 정리.
- JDK `HttpClient` 요청이 virtual thread interrupt로 실제 취소되는지 실검증(현재는 future cancel까지만 테스트).
- 목록 API에서 평가 시각 `now`를 이중으로 읽는 문제(요청당 1회 원칙과의 정합) 정리.
- 경로 응답에 `rentalAvailability`/`returnAvailability` 필드 추가 여부(명세 경로 계약, 현재 응답에 없음).

### 한계·미검증
- 실제 MySQL로 카탈로그를 적재하는 경로, 카탈로그가 있는 상태의 readiness 전환, 수집기 versioned 쓰기와의 통합, 다중 인스턴스 동작은 미검증.
- 실제 Kakao·서울 키, Kakao 캐시 약관, 실제 provider 지연에서의 breaker·504, JDK HttpClient의 interrupt 취소, 프록시 뒤 IP 판정(IPv6 /64 포함)은 미검증.
- 브라우저 화면(STALE 색상·테마 대비·버튼 안내·스크린리더)과 실제 429 흐름은 미확인(로직은 단위 테스트).
- 성능(p95)은 유예 상태로 측정하지 않았다.
