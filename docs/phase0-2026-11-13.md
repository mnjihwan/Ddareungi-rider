### 초기 실패 및 재실행

- 리뷰 단계에서 High 1건 발견: `start-local.sh infra`가 `MANAGEMENT_SERVER_PORT`를 셸 전체에 export해 수집기(Spring Boot)까지 8090을 상속 → 수집기 health 대기 실패·포트 충돌 가능. 수정: 전역 export 제거, backend/web 프로세스에만 전달, 포트 범위 검증(1~65535) 강화. 수정 후 `bash -n` 및 전체 테스트 재실행.
- Medium 1건: README가 `KAKAO_HTTP_*`, `APP_CORS_ALLOWED_ORIGINS`를 compose·스크립트가 전달하는 것처럼 읽힘 → 전달되지 않음을 문서에 명시.
- 로드맵 O5의 "(db, redis)" 표기를 구현에 맞춰 "db"로 정정.

### 한계·미검증

- Docker 이미지 빌드, non-root·BuildKit cache mount, 컨테이너 healthcheck, `compose --wait`: 이 환경에 Docker 데몬이 없어 **미실행**.
- GitHub Actions 실제 실행, 액션 버전의 릴리스 노트, branch protection(저장소 관리자 설정): 미확인.
- `start-local.ps1`: pwsh 없음, 미검증. `start-local.sh`의 수정 후 실제 infra 기동도 수집기 submodule 미초기화·Docker 없음으로 **미실행**(문법 검사만).
- MySQL·Redis가 실제로 살아 있을 때의 readiness UP, Redis만 중단됐을 때의 readiness 동작: 미검증.
- 실제 카카오 호출의 connect timeout 동작: 미검증.
- 리뷰 Low 항목(미반영, 후속 후보):
  - `InfraContextTest`/`LocalContextTest` 신규 테스트는 설정 값을 읽는 수준(`HealthEndpointGroups` 멤버 검증으로 강화 가능)
  - `KakaoHttpClientPropertiesTest`의 1초 미만 시간 단언은 느린 러너에서 flaky 가능
  - 관리 포트가 전 인터페이스에 바인딩(`management.server.address=127.0.0.1` 검토 가능)
  - real 모드에서 Vite `/actuator` 프록시는 502(웹에서 미사용)
- 재개 조건: Docker 가능한 환경 또는 CI 실행 결과 확보 시 O1·O2·O5 컨테이너 검증 수행.
