# 2026-10-13 데이터 확대 및 Python AI 기반 검증

## 적용한 초안 범위

`crowding_ai_discussion_summary.md`의 통계 기준 → LightGBM 비교 → 시간순 평가를 적용했습니다. 따릉라이더에 맞춰 정답은 **대여소별 10분간 대여 건수 / 반납 건수**입니다. 현재 잔여 자전거, 미래 잔여 수량, 사람 혼잡도와 다른 변수입니다. 입력은 대여소·요일·10분 시간대·월입니다.

TFT·TiDE·영상 군중 모델은 이번 기반 코드에 포함하지 않았습니다. 미래 재고 모델에 쓸 실제 관측의 시간 결합과 미래 정답 생성 함수는 따로 추가했습니다. UI 예측 영역은 유지하며, 오프라인 결과를 웹의 잔여 수량으로 자동 표시하지 않습니다.

10-06 시간별 이용 건수의 합 **160,967건**이 같은 날 일별 자료의 합과 일치했습니다(차이 0). 대여소 번호→현재 ID 매핑은 모든 새 시간별·일별 행에서 연결됐습니다. 과거 시점의 대여소 이전/폐쇄까지 검증한 매핑은 아닙니다.

[공식 월별 OD ZIP](https://data.seoul.go.kr/dataList/OA-21229/F/1/datasetView.do)의 09-18 CSV는 **UTF-8 헤더만 존재하는 199바이트 파일**이었습니다. 자동 문자셋 판별과 빈 파일 기록을 추가했고, `collection_run`에 `EMPTY`로 남겼습니다. 그날 수요를 0으로 만들지 않고 학습에서 제외합니다. 공급자가 나중에 정상 파일을 제공하면 다시 가져와 적재할 수 있습니다.

원본 다운로드는 실제 공식 파일 목록·다운로드 ID로 수행했습니다. 기간별 월 ZIP 선택, ZIP CRC/경로/용량 및 SHA-256 검증을 지원합니다. 현재 importer의 컬럼 계약은 2023-03 이후이며, 더 오래된 파일을 동일한 정답으로 가정하지 않습니다. 이번 실행에서 모든 연도의 전체 자료를 수집한 것은 아닙니다. [시간대별 원천 자료](https://data.seoul.go.kr/dataList/OA-15245/F/1/datasetView.do)는 날짜 범위의 24시간 전체 수집 스크립트로 추가 확보할 수 있습니다.

## 학습과 한계

학습 대상 범위는 2026-09-01~10-07의 유효 36일입니다. 첫 유효 날짜의 대여소 ID 정렬 순서에서 200개를 고르는 재현 가능한 실험 표본이며, 서울 전체를 대표하도록 표본추출한 것은 아닙니다. 최근 22개 학습 관측일, 7개 검증일, 7개 테스트일로 시간순 분리합니다. 검증에서 방법을 고르고 테스트는 최종 비교 보고에만 사용합니다.

원본 전체가 정상 적재된 날 중 활동이 확인된 대여소에 한해 비어 있는 시간대를 0으로 추정하는 옵션을 켰습니다. `inferred_zero`로 표시하며, 대여소의 종일 운영·휴업 이력까지 보장하지 않습니다. 이 가정을 확인하기 전에는 서비스 수준의 정확도를 주장할 수 없습니다. 누락 날짜와 하루 전체 미등장 대여소는 합성하지 않습니다.

관측 중앙값·25/75분위수·관측 일수의 기준 모델, 공통 LightGBM, 전체/대여소별/요일별/월별/높은 수요 구간의 MAE와 모델 저장·조회 코드를 제공합니다. 과거 분위수 범위를 미래 예측의 신뢰구간으로 표시하지 않습니다. 한 달 남짓의 자료로 연간 계절성이나 공휴일·날씨 효과를 검증하지 않았습니다.

실행 방법과 결과 파일 계약은 [AI README](../ai/README.md)에 있습니다. 모델·데이터는 `ai/artifacts`, `ai/data`에 저장하며 버전 관리에서 제외합니다. 설치한 패키지는 `ai/requirements-lock.txt`에 기록했습니다.

## 기능 검증

- Python 테스트 10개 통과: 날짜 분리, 미래 정답 누수 방지, 통계 보완, 결측 날짜, 미완료 원본, 중복, 행 수 제한, 실제 LightGBM 저장/재로딩/예측.
- Java 수집기 테스트 27개 및 빌드 통과. UTF-8/MS949/BOM, 잘못된 본문 문자, 빈 원본 처리와 기존 정상 데이터 보존을 추가 검증했습니다.
- 실제 DB의 3일 자료로 소규모 전체 흐름을 확인했으며, 이 결과는 `smoke_test_only`로 표시했습니다.
- 실제 5분 재고에서 미래 버킷이 존재하는 2,739개의 정답 결합 샘플을 생성했습니다. 재고 예측 모델 학습이나 서비스 성능 검증을 뜻하지 않습니다.
- 시간별 수집 기본값을 09시 한 시간에서 0~23시로 확대했습니다. 수집 후 환경변수 복원 시 빈 비밀번호 변수가 남는 문제도 수정했습니다.

## 최종 학습 결과

완료된 결과 디렉터리: `ai/artifacts/20261013-validated/{rentals,returns}`. 사용 데이터: `ai/data/20261013-003906`.

각 대상별 학습 633,312행, 검증 201,600행, 테스트 201,312행으로 총 1,036,224개의 대여소·10분 샘플을 사용했습니다. 9월 1~23일(09-18 제외)로 학습, 9월 24~30일로 검증, 10월 1~7일로 테스트했습니다. 표의 MAE 단위는 건/대여소/10분이며 낮을수록 좋습니다.

| 대상 | 통계 검증 MAE | LightGBM 검증 MAE | 통계 테스트 MAE | LightGBM 테스트 MAE | 검증으로 선택한 방식 |
| --- | ---: | ---: | ---: | ---: | --- |
| 대여 수요 | 0.3488 | 0.4269 | 0.3992 | 0.4325 | 통계 |
| 반납 수요 | 0.3462 | 0.4221 | 0.3923 | 0.4240 | 통계 |

테스트에서 높은 수요 구간의 MAE는 대여 1.1778→0.9365, 반납 1.1539→0.9203으로 LightGBM이 낮았습니다. 그러나 사전에 정한 전체 검증 MAE 기준으로 두 대상 모두 통계가 선택됐습니다. 테스트를 보고 기준이나 모델 설정을 바꾸지 않았습니다.

이 실험의 테스트 샘플 약 75%는 빈 구간을 0으로 추정한 값입니다(대여 75.20%, 반납 75.39%). 전체 MAE만 보고 실제 이용 가능성이나 고갈 탐지 성능을 주장하면 안 됩니다. Poisson 모델은 평균 건수를, 통계 기준은 중앙값을 대표하므로 희소한 건수의 MAE에서는 통계가 유리할 수 있습니다. 실제 운영 이력 검증·고갈 목적에 맞는 정답·추가 기간의 검증이 필요합니다. 한 번의 결과로 통계가 모든 조건에서 더 우수하다고 결론내리지 않습니다.

두 결과 모두 `offline_experiment`, `production_ready=false`입니다. 요일·시간대 이용 패턴의 기반 코드와 저장 모델까지 검증했고, 경로 도착 시 잔여 수량 예측은 아직 서비스에 연결하지 않았습니다.

```powershell
.\.venv-ai\Scripts\python.exe -m ddareungrider_ai.cli predict --model ai/artifacts/20261013-validated/rentals --station ST-10 --weekday 1 --hour 18 --minute 20 --month 10
```

Windows 한글 경로에서 LightGBM의 네이티브 모델 파일 저장이 실패하는 문제는 모델 문자열을 Python의 UTF-8 파일 입출력으로 저장·복원하도록 수정했습니다. 한글 경로의 저장·재로딩도 테스트합니다. 처음 저장에 실패한 `20261013-003906` 모델 디렉터리는 완료된 결과가 아니며 위 `20261013-validated`를 사용합니다.

완료된 두 LightGBM 모델을 한글 절대 경로에서 다시 읽어 각각 테스트 예측 100개가 저장값과 일치함을 확인했습니다(허용 오차 1e-10). 통계 기반 조회도 실제 저장 파일로 실행했습니다. 작업 후 MySQL·Docker를 종료했으며 5173/8080/8081/3307/6380 포트에 실행 중인 서비스가 없음을 확인했습니다.
