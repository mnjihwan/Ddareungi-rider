## 2. A2 → A1 (+X1), 한 브랜치에서 순서대로

### 2.1 현재 상태 [사실]
- `B:global/response/ApiResponse.java`는 `record ApiResponse<T>(T data)`뿐, 에러 바디는 `B:global/exception/ErrorResponse.java`의 `{code,message}`.
- `GlobalExceptionHandler`는 `RouteException`, `ConstraintViolationException`, `IllegalArgumentException`만 처리. 나머지(`ResponseStatusException`, `MethodArgumentNotValidException`, 파라미터 누락/타입 불일치, JSON 파싱 오류, `DataAccessException`, 405/404/415/406, 일반 500)는 Spring 기본 바디.
- 도메인 record를 응답으로 직접 노출: `Station`, `PlaceSearchController.Place`, `PlanBikeRoute.Plan`, `RouteController.Status/Request`, `StatusController`의 `Map`.
- 정적 리소스 없음. Actuator는 관리 포트 8090 별도 child context.

### 2.2 envelope·핸들러 설계
- 성공: `ApiResponse<T>(boolean success, T data, Meta meta, Instant timestamp)`, `ApiResponse.ok(data)` 시그니처 유지, requestId는 요청 attribute/MDC에서 읽음(요청 밖 호출은 null 허용), `Clock` 주입.
- 실패: `ApiErrorResponse(success=false, ErrorBody{code,message,details[{field,reason}]}, Meta, timestamp)`, `data` 없음. `field`는 경로 마지막 노드.
- `Meta`: `requestId` 항상, `partial`/`warnings`는 `@JsonInclude(NON_NULL)`로 생략.
- `ErrorCode` enum(명세 10장 코드 + HTTP status), `ApiException extends ResponseStatusException`(기존 테스트 호환), `InvalidCoordinateException extends IllegalArgumentException`(`Location`에서 던짐).
- `GlobalExceptionHandler extends ResponseEntityExceptionHandler`, `handleExceptionInternal` override. `@RestControllerAdvice`에 basePackages 제한 없음. `ResponseBodyAdvice` 자동 래핑 금지(관리 child context가 advice를 상속해 Actuator 응답이 감싸일 위험 [추정]). 제외: Actuator, 204, CORS 거부 403.
- `RouteException` 처리: ① `code`가 ErrorCode 이름과 같으면 그대로 ② 아니면 레거시 매핑표 ③ 없으면 500 + 경고 로그. HTTP status는 ErrorCode 기준(예외 객체 status 미사용). 내부 정보는 로그에만(requestId 포함).
- `IllegalArgumentException` → 400 규칙은 유지(위험: 내부 IAE도 400 [추정]).

### 2.3 A2
`global/web/RequestIdFilter`(OncePerRequestFilter, 최우선): 허용 형식 `^[A-Za-z0-9_-]{1,64}$`, 불일치 시 UUID 생성, 응답 헤더는 체인 실행 전에 설정(에러 응답에도 부착), MDC `requestId`+요청 attribute, `finally`에서 MDC 제거, 로그 패턴에 `%X{requestId:-}` 추가(`application.yml`).

## 3. E2
- `WalkingRouteProvider`, `BicycleRouteProvider` 인터페이스 신설: `configured()`, `attribution()`, `forRequest()`, `durations(sources, dests)`, `route(from, to)`. 반환은 기존 `RouteProvider.Leg`.
- 기존 `RouteProvider`는 내부 엔진 SPI로 유지, profile 고정 어댑터 2개(`EngineWalkingRouteProvider`, `EngineBicycleRouteProvider`). 엔진 선택은 `routing.provider` 하나 유지.
- 어댑터는 엔진의 UNAVAILABLE/LIMIT/AUTH를 각각 `WALK_ROUTE_PROVIDER_ERROR`/`BIKE_ROUTE_PROVIDER_ERROR`(502)로 변환. `NO_ROAD_ROUTE` 의미 유지.
- `PlanBikeRoute(StationSearchPort, WalkingRouteProvider, BicycleRouteProvider, enabled)`. `configured()` = enabled && 두 provider configured. **`Plan`, `execute(Location,Location,String,String)`, `RouteException`(`status`/`code`), `RouteProvider.Leg/Step` 시그니처 불변.**
- 테스트: `PlanBikeRouteTest` mock 2개로 분리, 어댑터 테스트 신규, Kakao/ORS 엔진 테스트 유지.
