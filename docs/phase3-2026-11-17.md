## 2. A6 — `POST /api/v1/routes/search`

### 현재 [사실]
- `RouteController`는 `POST /plan`만. `RoutePlanRequest`는 origin·destination·departureStationId·arrivalStationId. `PlanBikeRoute`: 반경 1000m 고정, 500m 안 후보 우선(없으면 1km에서 최대 3개), 최소 시간 조합 1개만 반환, 재조회 후 수량 없으면 409 `RENTAL_STOCK_CHANGED`.
- `KakaoRouteClient`: 요청 단위 캐시, matrix는 셀 하나라도 provider 오류면 전체 취소. 자전거 `route_mode=BIKE_ONLY` 고정. 호출 예산 도보 6+자전거 9=15회.
- `ErrorCode`에 `UNSUPPORTED_ROUTE_OPTION`(422)·`PAYLOAD_TOO_LARGE`(413)·`RENTAL_STOCK_CHANGED`(409), `WarningCode.PROVIDER_PARTIAL_FAILURE` 존재. `validationCode`는 필드명 기준이라 `options.*`는 자동 `INVALID_PARAMETER`.
- 웹: `W:lib/api.ts`(`/routes/plan`), `RoutePlanner.tsx`(legs·steps·attribution·대여소 지정), `StationMap.tsx`(`leg.path` Polyline, `fitRoute`), `App.tsx`. mobile은 `/routes/plan` 미사용.

### 명세(13.1)와 차이 → 처리
| 항목 | 현재 | 명세 | 처리 |
|---|---|---|---|
| 옵션 | 없음 | `options{stationSearchRadiusMeters 100~5000=1000, maxWalkingDistanceMeters 0~10000=1000, preferBikeRoute=true, excludeStationsWithoutBikes=true, maxCandidates 1~5=5}` | `@Valid` record 기본값 |
| 응답 루트 | 단일 Plan | `{recommended, alternatives[]}` | 변경 |
| 대여소 | `departureStation`/`arrivalStation` | `originStation`/`destinationStation` | 이름 변경 |
| 구간 | `legs[{mode,path,steps}]` | `segments[{type WALK/BIKE, distanceMeters, durationSeconds, encodedPolyline, bikeRoadPreferred}]` | path→Encoded Polyline, `steps`는 확장 필드 유지 |
| 합계 | `distanceMeters`, `durationSeconds` | `totalDistanceMeters`, `estimatedDurationSeconds`, `walkingDistanceMeters`, `bikeDistanceMeters` | 구간 정수 반올림 후 합 |
| 가용성 | 없음 | `rentalAvailability`(AVAILABLE_AT_FETCH/UNAVAILABLE_AT_FETCH/UNKNOWN), `returnAvailability=UNKNOWN` | 추가 |
| 부분 실패 | 하나면 전체 실패 | 200+partial | matrix 오류 수집 방식 변경 |

### 변경
1. `PlanBikeRoute`를 일반화: `RouteSearchCriteria(origin, destination, options, pinnedDeparture, pinnedArrival)` → `RouteSearchResult(ranked, partial)`. 3×3 쌍(같은 대여소 제외) 평가, 정렬 총 소요시간→도보거리→총거리→출발ID→도착ID, 상위 `maxCandidates`개 중 첫째가 `recommended`. `maxWalkingDistanceMeters`는 두 WALK 구간 실제 거리 합으로 필터(provider가 거리도 반환하도록 확장). `excludeStationsWithoutBikes=false`는 STALE·0대 후보 포함+`rentalAvailability` 계산(true는 현재 D2 결정표 유지).
2. 대안 비용: Kakao는 모든 쌍을 directions로 이미 계산·요청 단위 캐시하므로 추가 호출 0회(총 15회). ORS는 최대 약 11회 추가 가능 [추정], deadline 10초 유지.
3. 부분 실패: matrix에서 provider 오류 셀과 경로 없음(null)을 구분해 기록.
4. Encoded Polyline: 신규 `B:routing/presentation/EncodedPolyline`(정밀도 1e5, 위도·경도 순서, 반올림한 정수끼리 delta, 0에서 먼 쪽 반올림), 웹 `W:lib/polyline.ts` 디코더. 공통 테스트 벡터 Google 예시(`_p~iF~ps|U_ulLnnqC_mqNvxq`@`)로 왕복 검사. 0거리 WALK도 2점.
5. 본문 16 KiB: POST `/api/v1/**` 인터셉터(Content-Length>16384 → `ApiException(PAYLOAD_TOO_LARGE)`), chunked는 제한 스트림+`HttpMessageNotReadableException` 원인을 413으로 매핑(`GlobalExceptionHandler` 이 분기만 수정, G1 독점).
6. `KakaoRouteClient` base URL을 설정(`kakao.maps.base-url`, 기본 `https://dapi.kakao.com`)으로 외부화해 로컬 stub으로 e2e 가능하게 한다. 모드(BIKE_ONLY/SHORTEST)를 요청 단위 캐시 키에 포함.
7. 표현 계층: `RouteSearchRequest`/`RouteSearchResponse`(`recommended`, `alternatives`, `RouteResponse{routeId, totals, originStation, destinationStation, segments, rentalAvailability, returnAvailability}`), `routeId`=`route-`+UUID 앞 12 hex(저장 안 함), 대여소는 `StationViewMapper` 한 시점으로 판정. `/routes/plan`은 어댑터로 유지(응답 형식 불변, 헤더만 추가).
- 허용: `B:routing/**`, `GlobalExceptionHandler`(413 분기만), `ApiContractTest`·route 테스트, `R:application.yml`(`routing.search`·`kakao.maps` 키만 추가). 금지: `station/**`, `global/resilience/**`, `global/ratelimit/**`, `web/**`.

## 5. O7 — CD

- 현재 [사실]: `ci.yml`의 docker job은 빌드만, compose backend readiness는 8090, **Rate Limit 키가 `getRemoteAddr()`**(프록시 뒤에서 한 키로 묶임), 웹 운영 호스팅 구성 없음.
- 신규 파일: `.github/workflows/deploy.yml`(트리거 `workflow_run`(CI success·main)+`workflow_dispatch(image_tag)` 롤백용, `permissions: id-token: write, contents: read`, `environment: production`, `concurrency: deploy-production`(취소 안 함), 공식 `aws-actions/*`·`docker/*`·`actions/*`만 사용하고 커밋 SHA 고정[버전은 확인 필요], OIDC→ECR push(태그 SHA)→digest→`aws ssm send-command`로 `deploy.sh <digest>`), `deploy/ec2/deploy.sh`, `deploy/ec2/nginx/*.conf`, `deploy/ec2/backend.env.example`, `deploy/ec2/bootstrap.md`, `deploy/aws/*.json`(OIDC trust policy 템플릿, 최소 권한 정책, ECR lifecycle), `deploy/observability/`(prometheus·grafana compose).
- `deploy.sh` blue/green [추정]: ECR 로그인·pull(digest) → 활성 색 판정 → 반대 색 포트로 새 컨테이너(관리 포트 미공개) → readiness 확인(실패 시 새 컨테이너 제거·exit 1, 기존 유지) → upstream 파일 원자 교체·`nginx -t && nginx -s reload` → 프록시 경유 스모크(실패 시 되돌림) → 기존 컨테이너 drain 후 stop → 이전 digest 기록. 롤백은 `workflow_dispatch(image_tag=이전 SHA)`. 백엔드에는 DB 마이그레이션이 없어 이미지 롤백은 안전하다 [사실: Flyway는 수집기].
- 프록시: nginx가 `X-Forwarded-For $remote_addr`로 덮어써 위조 방지, 앱은 env `SERVER_FORWARD_HEADERS_STRATEGY=native`(yml 미수정). **forwarded 설정이 틀리면 대량 429가 나므로 배포 전 확인 필수**.
- 사용자 제공 값(자리표시자): AWS 계정 ID, 리전(기본 ap-northeast-2 가정), ECR 저장소명, GitHub OIDC provider·역할 ARN, EC2 인스턴스 ID/태그, Environment 승인자, 도메인·TLS 방식, MySQL·Redis·수집기 운영 위치. 장기 AWS 키는 GitHub에 두지 않는다(OIDC), 런타임 비밀은 SSM SecureString.
- 검증: PyYAML 파싱, `bash -n`, 가짜 docker·nginx·curl 하네스로 `deploy.sh`의 성공·readiness 실패·스모크 실패 분기 실행. **불가**: Actions 실제 실행, OIDC, ECR push, SSM, EC2·nginx reload, TLS, 이미지 빌드(데몬 없음), 첫 배포 시 MySQL 대여소 데이터 존재(없으면 readiness 실패로 기존 버전 유지).
