# 따릉라이더(ddareungrider) 로컬 개발

현재 서비스 클라이언트는 PC/모바일 브라우저용 `Ddareungi-rider/web`입니다. 기존 `mobile` 디렉터리는 이전 Expo PoC이며 로컬 실행 대상이 아닙니다.

Python 기반 대여·반납 수요 학습은 [AI 실행 안내](ai/README.md)를 참고하세요. 요일·10분 통계와 LightGBM을 시간순으로 평가하고 결과를 저장하는 오프라인 기반 코드입니다. 실제 웹 예측 연결 전 단계이며, 원본 수집 방법은 [데이터 수집 안내](docs/data-collection.md)에 있습니다.

## v0.1.0 — 1차 웹 기능 릴리스

지도, 장소·대여소 검색, 실시간 수량, 즐겨찾기와 도보→따릉이→도보 길찾기를 포함합니다. AI 미래 잔여 수량 예측은 아직 제공하지 않습니다. 구현 범위, 검증 결과와 운영 전 확인사항은 [릴리스 기록](docs/releases/0.1.0.md)을 참고하세요.

## 저장소 받기

통합 저장소의 릴리스 브랜치와 수집기 submodule을 함께 받습니다. 후속 개발은 `develop` 브랜치에서 진행합니다.

```powershell
git clone --branch main --recurse-submodules https://github.com/mnjihwan/Ddareungi-rider.git ddareungi
cd ddareungi
```

이미 복제했다면 `git submodule update --init --recursive`로 고정된 수집기 커밋을 받습니다.
루트에서 웹·백엔드(`Ddareungi-rider/`), 수집기(`bikeseoul_data/`), AI 소스(`ai/`), 공통 스크립트를 함께 관리합니다.
`.env.example`을 복사해 로컬 `.env`를 만들고 키와 DB 비밀번호를 입력하세요.
AI 원본 데이터·학습 모델·예측 파일·가상환경은 Git에 포함하지 않으며 수집·학습 절차로 생성합니다.

Git Flow 및 커밋 작성 방법은 [개발 규칙](docs/git-workflow.md)을 따릅니다. 검증된 작업은 `develop`에 통합하고 릴리스 시점에 `main`에 반영합니다.

## 네이버 지도에서 카카오맵으로 전환한 이유와 과정 (2026-10-10)

### 서비스 목표와 선택 이유

따릉라이더의 중심 기능은 실제 따릉이 이용자를 위한 **현재 위치 → 대여소 → 목적지 주변 반납 대여소 → 목적지** 길찾기입니다. 도보 → 자전거 → 도보의 세 구간을 우리 서비스 안에서 조회하고 지도에 표시해야 합니다. AI 예측은 부가 기능이며, PC와 모바일 웹에서 장소 검색·대여소 선택·길찾기를 이어서 사용할 수 있도록 구성합니다.

기존에는 네이버 지도 SDK와 장소 검색을 사용하고, 도보·자전거 경로는 openrouteservice(ORS)로 구현했습니다. 네이버의 공개 Maps Directions 5는 자동차 경로 API이므로 이 서비스의 이동 수단에 맞지 않았습니다. 네이버 지도 소비자 서비스에서 제공하는 길찾기 기능과 개발자가 호출할 수 있는 공개 API의 범위는 다릅니다. [네이버 Directions 5 공식 문서](https://api.ncloud-docs.com/docs/application-maps-directions5)

카카오맵은 공개 REST API로 도보·자전거 경로를 조회할 수 있고, 반환된 경로 좌표·거리·시간·한국어 안내를 서비스 화면에서 표시할 수 있습니다. 이에 국내 경로 API 조사 후 카카오를 선택했습니다. [카카오맵 경로 REST API](https://developers.kakao.com/docs/ko/kakaomap/rest-api), [전환 전 후보 조사 기록](docs/routing-api-research-2026-10-10.md)

사용자는 기존에 익숙한 지도 서비스의 UI가 사용성에 도움이 된다는 점을 중요하게 보았고, 지도 자체도 카카오로 통일하기로 결정했습니다. 지도·장소 검색·경로 조회를 같은 공급자의 인증과 도구로 관리하면 연동과 운영도 단순해집니다. 네이버 지도 위에 외부 경로를 표시하는 방식도 가능하므로 지도 전환 자체가 경로 기능의 기술적 필수 조건은 아닙니다. 카카오가 네이버보다 사용자 수·선호도에서 우세하다는 결론으로 선택한 것은 아니며, 앱 이용량을 API 이용량이나 우리 서비스의 UX 평가로 해석하지 않습니다.

### 인증을 먼저 확인한 과정

사용자 요청에 따라 기존 기능 변경에 앞서 카카오 인증 연동을 확인했습니다.

1. 같은 카카오 Developers 앱에서 JavaScript 키와 REST API 키를 발급하고 최상위 `.env`에 설정했습니다.
2. 카카오맵 사용 설정을 활성화하고 JavaScript SDK 도메인에 localhost 주소와 포트를 등록했습니다. 키 입력 형식·사용 활성화·허용 도메인 문제를 정리했습니다.
3. REST 키로 장소 검색, 도보 경로, 자전거 경로를 각각 실제 호출했습니다. 브라우저에서는 SDK 로딩과 실제 지도 타일 표시까지 확인했습니다.
4. 인증 성공 후 지도 SDK·검색·경로 구현을 교체하고 실제 데이터로 통합 검증했습니다.

현재 인증 변수는 `KAKAO_MAPS_JAVASCRIPT_KEY`와 `KAKAO_MAPS_REST_API_KEY`입니다. JavaScript 키만 웹 SDK에 전달하고 REST 키는 백엔드에서 사용합니다. 기본 실행에서는 네이버 키와 별도 ORS 키가 필요하지 않습니다. 구체적인 도메인 설정은 아래 카카오 인증 준비를 참고하세요.

### 코드와 화면 변경

| 영역 | 전환 전 | 현재 구현 |
| --- | --- | --- |
| 지도 로딩 | 네이버 JavaScript SDK | 카카오 SDK 로더와 로컬 TypeScript 선언 |
| 대여소 마커 | 네이버 SDK 오버레이 | 카카오 `CustomOverlay`에 React 버튼 연결 |
| 지도 이동·줌·화면 경계 | 네이버 SDK 메서드·이벤트 | 카카오 메서드·이벤트로 변환, 화면 경계별 대여소 조회 유지 |
| 장소·주소 검색 | 네이버 검색 및 지오코딩 | 서버의 카카오 Local 키워드 검색, 결과가 없으면 주소 검색 |
| 도보·자전거 경로 | ORS 기본 공급자 | `KakaoRouteClient`, 카카오 도보·자전거 REST 호출 |
| 경로 표시 | 네이버 `Polyline` | 카카오 `Polyline`, 도보 파란 점선·자전거 청록색 실선 |
| 서비스 이름 | 기존 프로젝트 표시명 | 사이트 제목·좌측 상단에 따릉라이더 / ddareungrider |

프런트엔드는 `StationMap.tsx`, `MapMarker.tsx`, `RoutePlanner.tsx`, 지도 로더와 Vite 환경변수 설정을 변경했습니다. 네이버 SDK 로더와 `@types/navermaps` 의존성은 제거했습니다. 백엔드는 `PlaceSearchController`를 카카오 Local API로 전환하고 경로 공급자의 기본값을 `kakao`로 설정했습니다. Compose, 로컬 실행 스크립트, `.env.example`도 새 인증 변수에 맞췄습니다. 실제 `.env`의 기존 네이버 키는 삭제하지 않았지만 현재 실행 경로에서 사용하지 않습니다. ORS 구현은 선택 가능한 기존 공급자로 남겨 두었습니다.

서울시 대여소·실시간 대여 수량의 데이터 공급자는 그대로 유지합니다. 지도 마커는 좌표에 고정하고 지도 이동 후 새 영역의 대여소를 조회합니다. 가까운 목록의 기본 500m 반경, PC의 왼쪽 목록 옆 상세 패널, 모바일 하단 패널, 즐겨찾기와 AI 예측 영역도 유지했습니다. AI 모델이 연결되지 않은 경우에는 예측 준비 상태를 표시합니다.

경로 선택은 출발·도착 주변 각 최대 3개 대여소의 실제 이동 시간을 비교합니다. 도보 최대 6회와 자전거 최대 9회로 검색 한 건에 최대 15회 호출하며, 최종 표시에는 그 검색 요청에서 받은 구간을 사용합니다. 다른 요청에 경로 응답을 재사용하거나 DB·Redis에 저장하지 않습니다. 대여소 수량의 최신성, 경로 연결 실패, 인증·이용량·빈 응답 오류도 처리합니다. 상세한 계산 규칙과 API 계약은 [길찾기 실행 안내](docs/routing.md)를 참고하세요.

### 검증과 남은 범위

백엔드 42개·웹 4개 테스트 및 운영 빌드를 통과했습니다. PC 1600×900과 모바일 390×844 브라우저에서 실제 카카오 API와 서울시 대여 수량으로 강남역 주변 → 역삼역 경로를 계산하고 세 경로선·네 지점을 표시했습니다. SDK 타일 로딩, 장소 검색, 마커 이동, 새 영역 대여소 조회, 즐겨찾기, AI 영역 유지, 목적지 변경 시 경로 제거도 확인했습니다. REST 키는 웹 빌드에 포함되지 않았습니다.

브라우저 위치는 테스트용 강남역 좌표를 사용했습니다. 실제 휴대폰 GPS와 현장 주행, 이동 중 자동 재탐색·음성 안내, 다양한 서울 구간의 경로 품질은 이번 검증에 포함되지 않았습니다. 아래의 네이버 검증 기록과 전환 전 API 조사 문서는 당시 상태를 남긴 기록이며, 현재 실행 설정은 이 README와 길찾기 실행 안내를 기준으로 합니다.

## 카카오 인증 준비

최상위 `.env`에 `KAKAO_MAPS_JAVASCRIPT_KEY`와 `KAKAO_MAPS_REST_API_KEY`를 설정합니다.
카카오 Developers 앱의 [카카오맵] > [사용 설정]을 ON으로 저장하고,
JavaScript 키의 SDK 도메인에 `http://localhost:5173`과 `http://127.0.0.1:5173`을 등록합니다.
휴대폰에서 LAN 주소로 테스트할 때는 해당 주소와 포트도 등록합니다.

로컬 웹 서버 실행 중 `node scripts/check-kakao-auth.mjs`로 지도 SDK·장소 검색·도보·자전거 인증을 확인합니다.
브라우저 점검은 `.local/browser-check`에 설치된 Playwright와 Edge를 사용합니다.
키 값은 출력하지 않으며 결과는 `.local/kakao-auth-result.json`에 저장합니다.
REST 키는 서버에만 전달하고 웹 빌드에 포함하지 않습니다.

2026-10-10 지도 SDK의 실제 타일, 장소 검색, 도보·자전거 API의 인증을 확인하고 카카오로 전환했습니다.

## 출발지·현재 위치 오류 수정 (2026-10-11)

출발지를 서울대입구역으로 바꿔도 이전에 지정한 교대역 대여소가 남아 있었고, 서버는 지정 대여소까지 출발지 1km 안에서만 찾았습니다. 이때 주변의 다른 대여소 유무와 무관하게 일반적인 대여소 없음 메시지를 반환했습니다. 출발지 변경 시 이전 지정 대여소를 해제하며, 직접 지정한 대여소는 반경 필터 대신 ID로 조회하도록 수정했습니다. 주변 대여소 없음·자전거 없음·최신 수량 확인 불가·지정 대여소 없음도 구분합니다.

서비스 요구에 근거 없이 추가했던 출발·목적지 50km 제한은 제거했습니다. 실제 경로 연결 가능 여부는 대여소 데이터와 카카오 경로 응답으로 판단합니다.

브라우저 현재 위치는 `enableHighAccuracy: true`, `maximumAge: 0`으로 요청하고 보고된 정확도를 표시합니다. PC에서 기기가 부정확한 좌표를 제공할 경우 코드만으로 실제 위치를 보장할 수 없으므로, 지도 중앙 핀을 출발 위치에 맞춰 **이 위치에서 출발**로 지정하는 기능도 추가했습니다. [고정밀 위치 요청의 의미](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition), [브라우저 위치 정확도](https://developer.mozilla.org/en-US/docs/Web/API/GeolocationCoordinates/accuracy)

재검증 스크립트는 `node scripts/check-route-origin.mjs`입니다. 서울대입구역 → 멀티캠퍼스 역삼 실제 경로, 이전 지정 대여소 초기화, 부정확한 위치 안내 및 지도 출발지 선택을 PC·모바일 브라우저에서 확인합니다.

백엔드 48개·웹 4개 테스트와 웹·백엔드 빌드가 통과했습니다. PC 1600×900과 모바일 390×844에서 서울대입구역 1번출구 대여소(출발지 직선거리 약 70m)를 선택했고, 멀티캠퍼스 역삼까지 실제 도로 경로 10,231m·3,304초를 확인했습니다. 위치 오차 안내는 테스트 브라우저에 50km 정확도의 좌표를 지정해 검증했으며, 사용자의 실제 PC 위치 정확도가 개선됐음을 의미하지 않습니다. 출발지 변경 시 지정 대여소 해제와 지도 중앙으로 출발지 지정도 통과했고 JavaScript 오류가 없었습니다.

## 장소 선택·추천 개선 (2026-10-11)

일반 장소 검색 및 길찾기의 출발·목적지 검색에서 결과를 선택하면 해당 좌표로 지도를 이동하고 선택한 장소 핀을 표시합니다. 검색어만 입력했을 때는 여러 결과 중 위치를 임의로 지정하지 않습니다.

고정 강남역·역삼역·신논현역 추천을 제거했습니다. 카카오 Local 카테고리 검색(`SW8`)으로 기준 위치 2km 안의 가까운 지하철역 최대 3곳을 조회하고 같은 역의 다른 호선은 합칩니다. 현재 위치가 있고 보고된 정확도가 500m 이내이면 **내 주변역**, 그렇지 않으면 지도 중심 기준의 **지도 주변역**으로 표시합니다. 새로운 위치 권한은 자동으로 요청하지 않습니다.

검색 결과를 선택한 기록은 최근 검색어 최대 5개로 관리하고 최근 2개를 추천 영역에 표시합니다. 같은 브라우저에서 새로고침 후에도 유지되며 **최근 장소 지우기**로 삭제할 수 있습니다. 저장 항목은 사용자가 입력한 검색어와 사용 시각뿐이며, 좌표·주소·카카오 응답을 저장하지 않습니다. 최근 장소를 누르면 해당 검색어로 다시 조회하고 결과를 선택합니다. 이 기록은 일반 장소·대여소 검색과 길찾기 검색에서 공유합니다.

대여소 상세의 **카카오맵에서 대여소 보기** 버튼을 제거했습니다. 내부 길찾기·즐겨찾기·AI 예측 영역은 유지합니다. 검증 스크립트는 `node scripts/check-place-experience.mjs`이며 PC·모바일에서 실제 카카오 장소 조회·지도 포커스·최근 기록 유지와 삭제·상세 버튼 제거를 확인합니다.

## 선택 장소 태그 해제·검색 자동완성 (2026-10-11)

검색으로 선택한 장소 태그는 지도 배경 또는 지도 안의 다른 장소를 클릭·터치하면 사라집니다. 새 검색어 입력·검색 실행·최근 장소 재검색에서도 이전 태그를 해제하고, 태그 자체의 닫기 버튼으로도 지울 수 있습니다. 표시만 해제하므로 길찾기의 출발지·목적지 입력값은 유지됩니다.

일반 검색과 출발지·목적지 검색은 두 글자 이상 입력하면 검색창 아래에 실제 카카오 장소와 보유 대여소를 제안합니다. 입력 후 350ms 기다렸다 조회하고 한글 조합 중에는 요청하지 않습니다. 입력어와 이름이 일치하는 지하철역을 우선하고, 나머지 장소와 가까운 대여소를 함께 표시합니다. 제안에는 이름·주소·종류를 표시하고 입력한 부분을 강조하며, 위·아래 방향키와 Enter로 선택하고 Esc나 바깥 클릭으로 닫습니다. 장소 연결에 실패하더라도 대여소 조회가 성공하면 대여소 제안은 유지합니다. 이름이 없는 대여소는 제안에서 제외합니다.

서버는 카카오 키워드 검색과 `category_group_code=SW8` 검색을 합치고 같은 장소를 중복 제거합니다. [카카오 Local 키워드 검색 공식 문서](https://developers.kakao.com/docs/ko/local/dev-guide#search-by-keyword)의 실제 카테고리 코드를 사용하며, 이름에 ‘역’이 들어간 음식점 등을 지하철역으로 취급하지 않습니다. API가 ‘서울대입’ 같은 부분 입력을 역으로 찾지 못하면 실제 보유 대여소 이름에서 확인한 역 이름 최대 2개로 검색을 보완하고, 지도 좌표는 카카오 응답에서 받습니다. 주소만 입력어와 일치하는 다른 역은 우선하지 않으며, 자동완성에는 이름·주소와 무관한 유사 결과를 제외합니다. 기존 카카오 인증키를 그대로 사용하고 API 응답을 로컬 저장소·DB에 저장하지 않습니다.

백엔드 54개·웹 14개 테스트 및 빌드를 통과했습니다. `node scripts/check-search-suggestions.mjs`는 PC 1600×900과 모바일 390×844에서 실제 카카오 응답 및 보유 대여소로 ‘서울대입’ 자동완성과 제출 검색의 지하철역 우선 표시, 지도 클릭·터치 및 새 검색의 태그 해제, 닫기 버튼, 키보드 선택, 출발지·목적지 검색과 입력값 유지, 한국어 조합, 가로 넘침을 확인합니다. 위치는 테스트 좌표를 사용하며, 연결 실패 검증에서는 장소 검색만 503으로 대체하고 대여소 데이터는 실제 API로 조회합니다.

## 대여소 마커 표시 개선 (2026-10-11)

기존에는 확대 수준과 관계없이 같은 64px 격자 칸의 대여소를 묶었습니다. 실제 마커가 겹치지 않아도 묶이거나 격자 경계에서 처리 결과가 달라지는 문제가 있어, 화면상 마커의 가로·세로 크기를 기준으로 겹침을 판단하도록 바꿨습니다. 연속해서 가까운 대여소 전체가 하나로 합쳐지지 않도록 묶음 안의 모든 대여소가 서로 겹치는 경우에만 합칩니다.

카카오 지도 레벨 4 이하의 가까운 배율에서는 묶음을 해제하고 각 대여소의 자전거 수량을 표시합니다. 겹치는 개별 마커는 주변 빈 공간으로 이동하고 연결선으로 원래 좌표를 표시합니다. 선택한 대여소는 원래 좌표를 우선 유지하며, 모든 마커와 연결선은 SDK 오버레이로 지도를 따라 움직입니다. 레벨 5 이상의 넓은 배율에서만 겹치는 대여소를 묶고, 묶음을 누르면 해당 대여소 영역으로 확대합니다.

웹 테스트 8개와 운영 빌드를 통과했습니다. `node scripts/check-marker-clusters.mjs`는 PC 2555×1214와 모바일 390×844에서 실제 카카오 지도 및 대여소 데이터로 레벨 3·4의 개별 표시, 레벨 5의 묶음, 마커 선택과 묶음 클릭 후 확대를 확인합니다. 개별 마커의 실제 화면 영역이 겹치지 않는지도 검사합니다. 브라우저 위치만 서울대입구역 주변 테스트 좌표를 사용합니다.

## 검색 입력 보정 (2026-10-15)

현재 검색은 Elasticsearch 없이 MySQL 대여소 목록과 카카오 Local API를 사용합니다. 대여소 검색·메인 검색·길찾기 자동완성에 공백/대소문자 정규화, 두벌식 한/영 키 매칭, 초성 검색 및 제한적인 오타 보정을 추가했습니다.

- `rkdskadur` / `rkdska역` → 강남역, `ㄱㄴㅇ` → 강남역, `강남얙` → 강남역 후보를 찾습니다. 입력한 글자를 자동으로 바꾸지는 않습니다.
- 정확한 부분 일치 → 한/영 키 일치 → 초성 일치 → 유사 이름 순으로 정렬합니다. 정확·한/영·초성 결과가 있으면 오타 추정 결과는 제외합니다. 자동완성과 장소 결과에 보정 이유를 표시합니다.
- 오타 비교는 한글 2음절 이상에만 적용합니다. 두벌식 키 기준 삽입·삭제·치환·인접 키 순서 교환을 비교하며, 2~3음절은 1회, 4음절 이상은 2회까지 허용합니다. 영문·숫자·기호는 오타로 추측하지 않습니다.
- 대여소 메타데이터는 프로세스 메모리에 최대 1분간 보관하고 이름·주소에서 검색해 상위 20건을 고릅니다. 실시간 대여 수량은 각 검색마다 Redis에서 조회합니다. 대여소 기준정보 변경은 다음 메타데이터 갱신 때 반영됩니다. 이는 수천 개 대여소를 위한 로컬 구현이며 ES 색인·분석기는 추가하지 않았습니다.
- 일반 장소는 원문 카카오 검색을 우선합니다. 관련 결과가 없고 영문 입력 전체를 완성된 한글로 변환할 수 있으면 변환어로 일반 검색을 최대 1회 추가합니다. 지하철역은 실제 대여소 이름에서 얻은 후보를 최대 2개까지 카카오에 확인합니다. 임의의 모든 상호에 대한 초성·오타 검색을 보장하지 않습니다.

프런트엔드·백엔드가 같은 검색 예제 파일을 사용해 한/영 키, 혼합 입력, 초성, 오타, 무관한 결과와 특수문자를 검증합니다. 백엔드는 샘플/DB 모드와 카카오 요청 흐름을, 웹은 자동완성 결과 유지·보정 안내를 함께 검증합니다.

검증 결과: 백엔드 테스트 64개, 웹 테스트 17개, 백엔드 JAR·웹 운영 빌드 통과. 샘플 대여소 데이터와 실제 카카오 API를 사용해 PC 1600×900·모바일 390×844에서 네 가지 입력 예제, 보정 안내, 키보드 선택, 검색 제출 및 길찾기 출발지 자동완성을 확인했습니다. 두 화면 모두 JavaScript 오류·가로 넘침이 없었습니다. DB 모드는 JDBC 단위 테스트로 확인했으며 이번 브라우저 검증에서 실제 MySQL 데이터 전체를 사용하지는 않았습니다. `scripts/check-search-corrections.mjs`가 브라우저 점검 스크립트이며 로컬 웹/백엔드와 기존 `.local/browser-check`의 Playwright·Edge가 필요합니다.

## 지도 기반 웹 인터페이스

좌표 입력 대신 장소·주소·대여소 이름 검색과 지도 이동을 사용합니다. PC에서는 왼쪽 검색/목록 바로 옆에 내용 높이에 맞춘 대여소 상세를 배치하며, 모바일에서는 지도 위 검색창과 3단계 하단 패널을 사용합니다. 위치 권한은 현재 위치 버튼을 누를 때만 요청합니다.

프로젝트 최상위 `.env` 설정:

- `KAKAO_MAPS_JAVASCRIPT_KEY`: 웹지도 SDK의 공개 키. JavaScript SDK 도메인에 포트를 포함한 `http://localhost:5173`, `http://127.0.0.1:5173` 및 사용하는 LAN/배포 주소를 등록합니다.
- `KAKAO_MAPS_REST_API_KEY`: 서버의 장소/주소 검색과 도보·자전거 길찾기에 사용합니다. 브라우저에 전달하지 않으며 VITE 접두사를 붙이지 않습니다. 네이버 인증키는 현재 실행 경로에서 사용하지 않습니다.
- `VITE_FORECAST_API_PATH`: 선택 사항. 제공된 기획서의 stationIds/horizons 요청 및 data 배열 응답 계약을 사용하는 예측 서비스의 경로입니다. 미설정이면 예측 준비 안내를 표시합니다. `ai/`의 오프라인 수요 모델과 이 잔여 수량 예측 API는 서로 다른 출력이며, 호환되는 예측 서버 연결은 아직 없습니다.

Vite는 최상위 `.env`를 읽습니다. 키 변경 후 웹 서버를 재시작합니다. 서버 REST 키는 `scripts/start-local.ps1` 또는 Compose를 통해 전달됩니다. 두 키는 같은 카카오 Developers 앱에서 발급합니다. 지도 연결 실패 시 명확히 표시한 도식 미리보기를 제공하며 실제 지도·경로나 예측값을 생성하지 않습니다.

즐겨찾기는 `bike:favorites:v1`에 ID와 저장 시각만 보관하고 최신 수량은 API로 조회합니다. 5분 이상 갱신되지 않은 수량은 0대와 구분합니다. 길찾기는 서비스 내부에서 세 구간의 경로·거리·시간을 표시합니다. 선택 사항인 외부 장소 정보 버튼은 카카오맵을 엽니다.

검증: `cd Ddareungi-rider/web`, `npm test`, `npm run build`. 카카오 전환 후 PC 1600×900(16:9), 모바일 390×844에서 실제 지도·장소 검색·서울시 대여 수량·도보/자전거 경로를 확인했습니다.
